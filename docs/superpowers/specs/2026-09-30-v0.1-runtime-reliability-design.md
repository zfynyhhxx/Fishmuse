# FishMuse V0.1 Runtime Reliability Design

## Goal

Repair the four failures observed in the real Windows desktop build: the extra console window, foobar2000 launch/connect recovery, an empty Library after scanning, and false music-action failures after otherwise successful AI responses.

## Evidence and root causes

- The running binary is `target/debug/fishmuse-desktop.exe`. `main.rs` selects the Windows GUI subsystem only for non-debug builds, so a debug launch owns a console whose closure terminates the process.
- The local application database contains one completed scan, 2,188 available `media_assets`, but zero `recordings`, `tracks`, and `library_fts` rows. `LibraryScanner` discards `ParsedTags` and commits only `MediaAssetWrite`; it never calls `LocalLibraryImporter`.
- The same database contains zero `conversations` and zero `conversation_messages`. `ConversationAgentStore::save_turn` appends child rows without creating the parent conversation, so the final persistence step fails after text has already streamed. The desktop event bridge maps every non-AI error to `Tool`, producing the misleading music-action banner.
- foobar2000 is registered through Windows App Paths, but the current user profile has no `foo_fishmuse` component. The Settings button currently only changes notice text and never launches foobar2000. The Rust backend already retries the named pipe and publishes a snapshot after connection.

## Design

### Windows process model

Apply `windows_subsystem = "windows"` to every Windows desktop build, including debug builds. Keep diagnostics in structured application logging and tests rather than a user-owned console. Add a Windows PE verification script that reads the built executable header and fails unless its subsystem is `WINDOWS_GUI`.

### Library scan-to-search pipeline

Make a parsed scan result retain both file identity and `ParsedTags`. The scanner will pass that result to `LocalLibraryImporter`, which already creates recordings, releases, artists, tracks, media assets, and FTS projections transactionally. Scanner-only asset batches remain for unchanged/moved assets and diagnostics.

Add a `projected` flag to `StoredMediaAsset`, derived from `track_id IS NOT NULL`. An existing matching asset is considered unchanged only when projected. This causes the next scan to repair V0.1 databases containing fingerprint-only media assets without deleting user data. The Library page refreshes its current query when a scan reaches a terminal state so newly imported tracks appear without editing the search field.

### Conversation persistence and error classification

`ConversationAgentStore::save_turn` will idempotently ensure the conversation parent exists before appending the turn. `SqliteConversationRepository::create` will use insert-if-absent semantics for the same user and conversation ID; a cross-user ID collision still fails at the foreign-key boundary.

The desktop bridge will classify only Library or Playback failures as tool failures. Storage failures during AI finalization will surface as a generic interrupted-service failure, never as a completed music action. The normal fixed path emits `turn_completed` and no failure event.

### foobar2000 recovery

Expose a narrow `launch_playback_backend` Tauri command. On Windows it asks the Shell/App Paths mechanism to open `foobar2000.exe`, which respects standard and custom install locations without exposing a path to the frontend. The existing `FoobarBackend` supervisor continues retrying the user-scoped named pipe; the frontend observes the existing service-state event when the component connects.

Settings will call the command, report launch errors, and explain that a persistent disconnected state means `foo_fishmuse` must be installed. FishMuse will not silently install or overwrite a real foobar2000 profile. Actual component installation remains an explicit operator action.

## Testing

- A scanner integration test proves one scan creates searchable tracks and a second scan repairs a legacy unprojected asset.
- Conversation persistence tests prove a first turn creates its parent and later turns reuse it without duplicate failures.
- Desktop event tests prove storage failures are not emitted as tool failures.
- IPC and Settings component tests prove the Start button invokes the launch command and reports success/failure.
- The Windows PE script validates the debug executable is GUI-subsystem.
- Run the focused suites, then all frontend and Rust tests, typecheck, lint, clippy, format, and a debug desktop build.

## External integration boundary

The code can launch and reconnect to foobar2000, but the live pipe cannot exist until `foo_fishmuse.dll` is installed in the active foobar2000 profile. Installing that generated DLL changes an external user profile and is not performed without explicit operator authorization.
