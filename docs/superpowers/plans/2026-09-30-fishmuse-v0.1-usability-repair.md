# FishMuse V0.1 Usability Repair Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make FishMuse the complete, fixed-shell user interface for browsing, starting, displaying, and controlling local playback without exposing or requiring direct foobar2000 interaction.

**Architecture:** Keep the frozen foobar v1 wire protocol intact, extend the existing domain adapter to expose capabilities already present in v1, and place a provider-neutral managed playback coordinator above `PlaybackManager`. Both Tauri commands and AI tools use that coordinator; the Tauri projection resolves safe library metadata and artwork while the React shell owns all user interaction and scrolling.

**Tech Stack:** Rust 2024, Tokio, SQLx/SQLite, Lofty, Tauri 2, React 19, TypeScript 5.9, Vitest/Testing Library, WebdriverIO/WebView2, Windows API.

**Spec:** `docs/superpowers/specs/2026-09-30-fishmuse-v0.1-usability-repair-design.md`

## Global Constraints

- Follow RED-GREEN TDD for every behavior change; read `superpowers:test-driven-development/references/writing-good-tests.md` before editing tests.
- Do not change or reinterpret `protocol/foobar-v1`; Stop and SetVolume must use its existing messages and fixtures.
- The normal UI and its errors must not name foobar2000; implementation identity is restricted to Advanced diagnostics.
- Frontend DTOs and AI context must not contain local paths, backend names, raw tags, artwork bytes sent to AI, credentials, or technical error context.
- Queue input is Track-ID-only, capped at 1,000 entries; history is capped at 100 entries; oversized input is rejected.
- Startup waits at most five seconds, shares one concurrent launch attempt, preserves each original operation ID, and never reissues an ambiguously accepted command.
- Artwork accepts only JPEG, PNG, or WebP and at most 5 MiB before base64 encoding.
- Mute is volume zero; values at or below `0.0001` project as muted; unmute restores the session's last non-zero volume or `1.0`.
- No profile overwrite, component installation, public push, deployment, or paid AI request is allowed by implementation or automated verification.

## Review Focus

- A failed hidden launch or five-second readiness timeout must leave Library usable and show one generic retry path; Task 4 tests both cases.
- Concurrent Play requests during startup must launch once but execute each distinct operation exactly once; Task 4 tests leader/follower behavior and operation IDs.
- Stale or out-of-order playback events must neither regress the display nor double-write listening history; Tasks 6 and 8 test revision rejection.
- Oversized queue/artwork input and non-finite volume must fail safely before an external boundary; Tasks 3, 5, and 6 test exact limits.
- Small windows, empty/tagless libraries, failed scans, and end-of-queue navigation must preserve visible controls and actionable state; Tasks 1, 2, 5, and 9 test these conditions.
