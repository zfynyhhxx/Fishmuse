# FishMuse V0.1 Muse Loop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 Windows 11 上交付一个个人优先、离线可用的 FishMuse V0.1：能够建立本地音乐库，通过可替换 Playback Backend 控制播放，并通过 provider-neutral AIService 使用 DeepSeek Responses API 完成带受控工具调用的流式音乐对话，同时冻结未来 AI-native Music Graph 所需的最小应用边界。

**Architecture:** 采用模块化本地单体。Tauri 2 + React 负责桌面壳和唯一主界面，Rust workspace 负责领域模型、SQLite、扫描、AI 与播放编排；应用层通过 AIService、PlaybackBackend 和版本化事件 contract 使用外部能力。当前 AgentRunner/DeepSeek 与 FoobarBackend/foobar2000 都位于稳定门面之后。Core 不读取 foobar 数据库，也不依赖任何云服务、AI credential 或已连接播放器才能浏览本地曲库。

**Tech Stack:** Windows 11；Rust 1.98.1 stable-msvc；Tauri 2；React + TypeScript + Vite；pnpm 11；SQLite/FTS5；Tokio；SQLx；Lofty；Reqwest/SSE；Windows Credential Manager；C++20 + Visual Studio 2022；foobar2000 SDK；Vitest + Testing Library；WebdriverIO Tauri service。

**Spec:** [中文批准规格](../specs/2026-09-27-fishmuse-v0.1-muse-loop-design.zh-CN.md)；[英文规格](../specs/2026-09-27-fishmuse-v0.1-muse-loop-design.md)

## Global Constraints

- Windows first；V0.1 不承诺 Linux 安装包，但所有领域端口不得直接暴露 Windows 类型。
- 个人优先、local-first。未配置 AI 或 foobar 时，本地扫描、曲库和搜索仍必须工作。
- V0.1 只实现一个本地用户，不实现远程注册、密码、云同步或多设备冲突处理；数据库仍保留 UserId 和所有权边界。
- FishMuse 自己扫描媒体文件并拥有自己的 SQLite 数据库；禁止读取、修改或逆向解析 foobar2000 数据库。
- V0.1 支持 .flac、.mp3、.m4a、.aac、.ogg、.opus、.wav、.aif、.aiff。CUE 在 V0.1 只生成明确的 unsupported_cue 诊断，V0.2 必须正式实现。
- 音乐文件只读。任何扫描、导入、规范化和封面处理都不得修改源文件或标签。
- 播放后端接口必须与 foobar 解耦；V0.1 只启用 foobar 后端，原生播放留给后续里程碑。
- Named Pipe 协议固定为 v1；4 字节小端长度前缀 + UTF-8 JSON；单帧最大 1 MiB；只允许同一 Windows 用户连接。
- 所有产生播放副作用的请求必须带 OperationId，并在超时重试时保持幂等。
- 开发期与 V0.x 的真实云端测试仅使用 DeepSeek；默认模型 deepseek-flash。OpenAI/GPT 不出现在 V0.1 运行时依赖、必需配置或 CI 中。
- DeepSeek API Key 只存 Windows Credential Manager；不得写入仓库、SQLite、日志、崩溃报告或前端持久化存储。
- 发给 DeepSeek 的内容只允许：用户消息、必要的曲目元数据、最近播放摘要和工具结果；禁止发送文件绝对路径、完整数据库、音频内容或其他秘密。
- AI 单轮最多执行 6 次工具调用；search_library 默认最多返回 20 条；未知工具、无效 JSON 或超过上限一律拒绝。
- 预算以整数 MicroYuan 计算。累计真实测试成本达到 ¥10 提醒；达到 ¥20 自动阻止新的 live AI 测试，除非用户显式重置预算。
- 单元测试、常规集成测试和 CI 使用 FakeAIProvider 或录制夹具，不调用真实付费 API。
- 100,000 首合成曲目的热缓存搜索 P95 小于 200 ms；播放命令正常路径 500 ms 内收到 ACK；扫描不得阻塞 UI。
- 所有 Rust 代码必须通过 cargo fmt、cargo clippy -- -D warnings 和 cargo test；前端必须通过 lint、typecheck 和测试。
- 每个任务严格执行红—绿—重构，完成后只提交该任务相关文件；不把多个任务压成一个大提交。
- 每个任务执行前检查工作树，保留用户已有修改；不得使用 git reset --hard 或覆盖不相关文件。
- Task 11 后、Task 12 前必须完成 Task 11.5 Architecture Contract Freeze；不得把 DeepSeekClient、AgentRunner 或 FoobarBackend 暴露为长期 Desktop/UI contract。
- `ContextEnvelope` 只承载 FishMuse 自身 UI 的结构化语义上下文；V0.1 不实现截图、OCR、全局 Capture、主动 AI 或多个 autonomous agents。
- AI application event 必须版本化并包含 turn id、严格递增 sequence 与稳定 payload；外部内容和 tool result 永远是 data，不是 instructions。
- AI 不直接写 Canonical Graph；V0.1 不新增 metadata/identity/merge/taste 写工具或 Proposal System。
- Music Provider 与 Playback Backend 是独立概念；V0.1 不实现流媒体 Provider，service state 使用 provider/backend-neutral 外壳。

## Review Focus

以下五类高风险行为必须在所属任务中有直接自动化证据：

1. 两个大小和修改时间相同但内容不同的文件，以及移动后的同一文件，不得被错误合并或重复导入。
2. Named Pipe 的跨用户连接、伪造握手、超长帧和乱序事件必须被拒绝。
3. 播放命令在 ACK 丢失后重试，不得执行两次播放、跳转或下一曲。
4. 迁移中断、磁盘写满或数据库损坏时，原数据库必须可恢复，错误必须可操作且不泄露敏感路径。
5. DeepSeek 流式函数调用中的未知工具、畸形参数和工具结果里的提示注入文本，不得越权执行。
