# FishMuse V0.1 Task 11.5 Architecture Contract Freeze Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Freeze the smallest provider/backend-neutral application contracts needed to assemble Task 12 without exposing `DeepSeekClient`, internal `AgentEvent`, concrete `AgentRunner`, or `FoobarBackend` as long-term UI dependencies.

**Architecture:** Add a narrow `AIService` facade over the completed Task 11 `AgentRunner`, a safe optional `ContextEnvelope`, a versioned and sequenced UI event envelope, and generic AI/playback service-state values. Keep all current DeepSeek, tool, cancellation, security, and playback behavior unchanged; future Control Plane, Provider, Taste, Curator, proactive-AI, capture, and native-playback functionality remains roadmap-only.

**Tech Stack:** Rust 1.98.1; futures/async-stream; serde/serde_json; UUID v7; Tokio cancellation; existing FishMuse domain, AI, and playback crates.

**Spec:** [Approved Chinese V0.1 design](../specs/2026-09-27-fishmuse-v0.1-muse-loop-design.zh-CN.md); [English mirror](../specs/2026-09-27-fishmuse-v0.1-muse-loop-design.md)

## Global Constraints

- V0.1 remains DeepSeek-only at runtime and keeps exactly the existing nine tools and six-tool-call cap.
- Core/Library behavior cannot depend on AI/network/credentials; non-playback behavior cannot depend on a connected backend.
- `ContextEnvelope` contains only structured FishMuse UI semantics and is always presented to the model as redacted untrusted data.
- No local path, API key, credential, database row, content fingerprint, or `technical_context` may cross the AI application boundary.
- AI events exposed to Desktop/Tauri contain contract version, UUID-v7 turn id, strictly increasing sequence, and typed application payload.
- Internal DeepSeek wire types, `AIEvent`, and `AgentEvent` remain behind `AIService`.
- AI does not gain Canonical Graph writes, new tools, screenshots, OCR, global capture, background jobs, proactive behavior, additional providers, or autonomous roles.
- Playback state is backend-neutral at the service boundary; a concrete backend appears only as optional diagnostic metadata.
- Every production behavior follows RED → GREEN → refactor, then the full relevant crate suites and strict Clippy/fmt gates.

## Review Focus

1. A `ContextEnvelope` containing a Windows/UNC/Unix path or sensitive-key-shaped object must reach the fake provider only as redacted untrusted data.
2. Each started turn must receive a distinct UUID-v7 id and envelopes whose sequence starts at 1 and increases exactly once per emitted internal event.
3. The serialized event contract must expose application event types only, never DeepSeek SSE names or provider response ids.
4. AI states `ready`, `not_configured`, and `unavailable`, plus playback states `ready`, `disconnected`, and `unavailable`, must serialize without requiring a concrete implementation.
5. Existing cancellation, tool-limit, prompt-injection, and provider interruption behavior must remain covered by the unchanged Task 11 suites.

- Produces: `AIServiceState { status, implementation }` and `PlaybackServiceState { status, implementation }`, where implementation metadata is optional diagnostics.
