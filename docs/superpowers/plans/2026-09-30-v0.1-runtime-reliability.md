# FishMuse V0.1 Runtime Reliability Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the real Windows desktop launch cleanly, populate and search scanned music, complete ordinary AI turns without a false tool error, and launch/reconnect to foobar2000 through the existing bridge.

**Architecture:** Repair each failed production boundary at its source while retaining the existing domain contracts. The scanner feeds the existing importer, the agent store ensures its parent aggregate, and the desktop shell exposes a generic playback-launch command while the existing backend supervisor owns reconnection.

**Tech Stack:** Rust, Tokio, SQLx/SQLite, Tauri 2, React 19, TypeScript, Vitest, PowerShell.

**Spec:** `docs/superpowers/specs/2026-09-30-v0.1-runtime-reliability-design.md`

## Global Constraints

- Keep local media paths, credentials, and technical error context out of frontend DTOs.
- Do not install into a real foobar2000 profile without explicit user authorization.
- Preserve generic AI and Playback application boundaries.
- Every behavior change starts with a failing regression test.

## Review Focus

- A legacy fingerprint-only media asset must be projected on rescan instead of skipped.
- A second AI turn in the same conversation must not fail on duplicate parent creation.
- A conversation ID owned by another user must not accept appended messages.
- A failed foobar launch must remain disconnected and show a recoverable UI message.
- Debug and release Windows executables must both use the GUI subsystem.
