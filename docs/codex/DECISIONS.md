# FishMuse V0.1 Decisions

Record only decisions that affect contracts, security, data integrity, architecture, compatibility, or later tasks.

| Date | Scope | Decision | Evidence / reason |
| --- | --- | --- | --- |
| 2026-09-28 | Codex execution | Use `gpt-5.6-terra` at medium reasoning with low verbosity for routine V0.1 work. | Reduces routine reasoning/output cost while retaining an implementation-capable model. |
| 2026-09-28 | Codex execution | Disable ordinary multi-agent tools and keep one primary implementation thread. | Historical FishMuse usage was dominated by child-session and review-chain context. |
| 2026-09-28 | Codex execution | Keep `on-request` sandbox approvals with `auto_review`. | Preserves workspace boundaries while reducing user interruptions for eligible approvals. |
| 2026-09-28 | Project memory | Store status, decisions, verification, and failures in `docs/codex`. | Lets new continuations recover from small durable files instead of the full conversation. |
| 2026-09-28 | foobar IPC v1 | Freeze v1 as a closed envelope/payload/message/capability contract and include `stop`, `set_volume`, and `get_state`. | The approved specification §9.1 requires those operations even though Task 6's initial Rust `PlaybackCommand` list omitted them; later adapters must converge on the stricter specification without weakening v1 closure. |
| 2026-09-28 | Task 8 build | Disable MSBuild `TrackFileAccess` in the CMake preset and generated SDK-independent test project. | On the recorded host, Tracker left `cl.exe` suspended; the same project completed with tracking disabled. Compiler warnings, tests, and dependency resolution remain unchanged. |
| 2026-09-28 | Named Pipe authentication | Perform one bounded pipe read before impersonating and comparing the client token SID, but do not decode JSON or dispatch commands until authorization succeeds. | Windows returns error 1368 when `ImpersonateNamedPipeClient` is called before the server has read client data. The explicit current-user/SYSTEM DACL remains the first access barrier. |
| 2026-09-28 | foobar component architecture | Keep framing, protocol, pipe service, idempotency, and PlaybackFacade independent of the foobar SDK; isolate SDK calls in the pending adapter. | This permits real security/contract tests without committing SDK artifacts while preserving a narrow, testable boundary for the pinned 2026-09-17 SDK. |
| 2026-09-28 | Named Pipe discovery | Define `UserSidHash` as lowercase hexadecimal SHA-256 over the canonical Windows SID string's UTF-8 bytes. | The protocol previously omitted the byte encoding and the first C++ draft hashed UTF-16 storage, which a natural Rust implementation would not reproduce. A fixed SID vector now locks cross-language discovery. |
| 2026-09-28 | Foobar snapshot identity | Preserve the schema's nullable `trackId` for every playback status, including `playing` and `paused`; never reuse a stale FishMuse ID for a track started directly inside foobar. | The real SDK can report a current media handle that was never resolved by FishMuse, while privacy rules forbid returning its path. Rust and C++ had added a stricter invariant absent from the shared Schema. Cost if wrong: consumers must render active playback with unknown identity rather than assuming every active item belongs to the FishMuse library. |
| 2026-09-28 | Foobar SDK adapter | Play trusted local handles through a dedicated `FishMuse Playback Bridge` playlist, and defer all playback-callback snapshots outside the SDK callback stack. | The SDK exposes arbitrary-handle playback through playlist operations, while `playback_control` explicitly forbids calls from global callbacks. The bridge does not activate the playlist or access database files; deferred events are cancellable before pipe shutdown. |
| 2026-09-29 | Wrong-SID integration | Validate the DACL with a real secondary-user interactive token, a current-user positive control, and synchronous `CreateFileW` under impersonation instead of requiring a cross-user child process. | Host policy denies cross-user process creation before pipe access. The plan requires a repeatable real-token Windows integration test, not a separate process; direct Win32 access under the verified different SID tests the same kernel DACL and yields the exact error code. |
| 2026-09-29 | GitHub publication | After Task 8 passes and a secret/binary boundary audit is clean, publish the repository as public and push each subsequent task-level commit; do not create a PR or deploy. | The user's latest explicit instruction overrides the earlier no-push constraint while retaining the plan's commit granularity and privacy/security constraints. Public repository `zfynyhhxx/Fishmuse` now tracks the task branch. |
| 2026-09-29 | Foobar source-path boundary | Inject a local `MediaPathResolver` through `FoobarConfig`; keep `PlayableSource` and public/app-facing commands logical-ID-only, and send the resolved path only across the same-user local pipe without logging it. | `PlaybackBackend::execute` receives a `MediaAssetId`, while foobar requires a trusted local path. Resolver injection preserves the library/backend boundary and prevents UI or AI exposure without coupling playback to SQLite. |
| 2026-09-29 | Foobar reconnect revisions | Track the plugin's `(session_id, sequence)` separately and project every accepted authoritative/incremental update onto a process-local monotonic `PlaybackSnapshot.revision`. | A restarted plugin legitimately resets sequence to zero, but the existing playback state machine rejects stale or non-increasing domain revisions. Session isolation plus monotonic projection accepts a restart without allowing an old connection's late event to overwrite current state. |
| 2026-09-29 | AI provider boundary | Expose only provider-neutral requests/events, permit only `https://api.deepseek.com/responses` with `deepseek-flash`, and release function calls only after the arguments-done event validates complete JSON. | Prevents endpoint/key exfiltration, hides DeepSeek-specific wire types from the agent layer, and makes partial streamed arguments non-executable. |
| 2026-09-29 | AI credentials | Store the DeepSeek key as a current-user Windows Generic Credential at `FishMuse/DeepSeek`; app-facing status exposes only a configured boolean, while unsupported platforms return a typed configuration error. | Keeps the raw key out of SQLite, settings, logs, and frontend commands. The reversible Windows integration test verified save, overwrite, read, and delete without leaving a credential behind. |
| 2026-09-29 | AI pricing and budget | Represent CNY prices in a dated `PriceSchedule`, calculate conservative micro-yuan totals, and apply the hard stop only to explicitly marked live tests; normal conversations continue with estimates and warnings. | Pricing changes remain auditable, concurrent spend accumulation is atomic, and development spend cannot permanently disable the user's normal product flow. |
| 2026-09-29 | Agent tool continuation | Continue tool rounds with the provider response ID and standard `function_call_output` items, and reject duplicate properties while decoding the completed argument JSON. | Preserves the DeepSeek Responses protocol, prevents partial or ambiguous arguments from executing, and keeps provider wire details below the agent boundary. |
| 2026-09-29 | AI tool authority | Register exactly nine case-sensitive music tools, validate closed schemas locally, cap each turn at six tool executions and searches at twenty results, and generate UUIDv7 OperationIds locally for every playback side effect. | Model output cannot expand permissions, inject backend paths, choose idempotency keys, or bypass PlaybackManager persistence. |
| 2026-09-29 | AI/library boundary | Resolve a model-supplied TrackId to the minimal local `PlayableSource` through the user-scoped `LibraryQueryPort`; never expose or accept a filesystem path in the AI tool contract. | Lets `play_track` reach the trusted playback layer while preserving library isolation and path privacy. |
| 2026-09-29 | Agent context persistence | Load only the selected conversation, retain at most twenty historical tool results as explicitly untrusted redacted data, and persist assistant text with provider, model, terminal status, usage, and estimated cost in a safe envelope. | Supports multi-turn recovery and auditability without storing API keys, technical context, database rows, fingerprints, or local paths. |
| 2026-09-29 | Product architecture | Define FishMuse as the sole primary frontend over a Canonical Music Graph and future Personal Taste Model; keep Music Providers and Playback Backends as separate replaceable contracts. | Prevents foobar2000 or any streaming platform from becoming the product identity or canonical ownership boundary. |
| 2026-09-29 | AI application boundary | Insert Task 11.5 before desktop assembly and require Tauri/AppState to depend on provider-neutral `AIService`, optional `ContextEnvelope`, versioned sequenced AI application events, and generic service state rather than `DeepSeekClient` or concrete `AgentRunner`. | Freezes the lowest-cost seam before Task 12 while preserving the completed Task 11 engine and the DeepSeek-only V0.x runtime constraint. |
| 2026-09-29 | AI context and security | Prefer structured semantic context from FishMuse UI, treat it and all external/tool content as untrusted data, and defer screenshots/OCR/global capture. | Preserves prompt-injection and privacy boundaries while enabling later Current View, Selected Entity/Text, Now Playing, and Contextual Ask without redesigning the command contract. |
| 2026-09-29 | AI write governance | Keep Canonical Graph writes deterministic and outside V0.1 AI tools; future material AI changes follow Observe → Reason → Propose → Review → Commit → Learn through Proposal/Revision/Audit. | Avoids silent graph corruption and keeps high-impact mutations reviewable and reversible without prematurely implementing the proposal system. |
| 2026-09-29 | Roadmap scope | Add a separate V0.1.1 Architecture Hardening milestone, then stage AI Curator/Music Graph, Unified Providers, Contextual AI, and Taste/Active AI across V0.2–V0.5; switch Native Playback only after maturity gates. | Prevents architecture vision from expanding V0.1 user features or forcing an immature backend to meet a version date. |
| 2026-09-29 | Desktop composition root | Keep `AppState`, Tauri commands, frontend contracts, and event payloads dependent only on `AIService`, `PlaybackApplicationService`, and generic service-state DTOs; construct DeepSeek and foobar adapters only in `src-tauri/src/lib.rs`. | Lets Fake or future implementations replace either service without changing presentation contracts while retaining DeepSeek-only and foobar-backed V0.x production behavior. |
| 2026-09-29 | Runtime AI credential reload | Wrap the active application-level AI service in a reloadable provider-neutral slot; successful secure key save/delete swaps the service immediately without exposing or retaining the key in UI state. | Settings can activate or deactivate AI without a process restart, while `AppState` still targets only `AIService` and Windows Credential Manager remains the credential owner. |
| 2026-09-29 | Desktop playback path boundary | Derive the same-user foobar pipe name at the composition root and resolve `MediaAssetId` to a native path only inside a user-scoped SQLite `MediaPathResolver`; omit backend and path data from playback DTOs. | V0.1 can reach the existing secure bridge without making foobar or filesystem paths part of the long-term UI/application contract; V0.1.1 still owns richer discovery and provisioning. |

When adding a row, prefer a concise decision and link to the relevant test, plan section, or commit.
