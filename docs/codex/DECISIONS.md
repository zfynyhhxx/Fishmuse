# FishMuse V0.1 Decisions

Record only decisions that affect contracts, security, data integrity, architecture, compatibility, or later tasks.

| Date | Scope | Decision | Evidence / reason |
| --- | --- | --- | --- |
| 2026-09-28 | Codex execution | Use `gpt-5.6-terra` at medium reasoning with low verbosity for routine V0.1 work. | Reduces routine reasoning/output cost while retaining an implementation-capable model. |
| 2026-09-28 | Codex execution | Disable ordinary multi-agent tools and keep one primary implementation thread. | Historical FishMuse usage was dominated by child-session and review-chain context. |
| 2026-09-28 | Codex execution | Keep `on-request` sandbox approvals with `auto_review`. | Preserves workspace boundaries while reducing user interruptions for eligible approvals. |
| 2026-09-28 | Project memory | Store status, decisions, verification, and failures in `docs/codex`. | Lets new continuations recover from small durable files instead of the full conversation. |
| 2026-09-28 | foobar IPC v1 | Freeze v1 as a closed envelope/payload/message/capability contract and include `stop`, `set_volume`, and `get_state`. | The approved specification §9.1 requires those operations even though Task 6's initial Rust `PlaybackCommand` list omitted them; later adapters must converge on the stricter specification without weakening v1 closure. |
| 2026-09-28 | Task 8 build | Disable MSBuild `TrackFileAccess` in the CMake preset and generated SDK-independent test project. | On the recorded host, Tracker left `cl.exe` suspended; the same project completed with tracking disabled. Compiler warnings, tests, and dependency resolution remain unchanged. |
| 2026-09-28 | Named Pipe authentication | Perform one bounded pipe read before impersonating and comparing the client token SID, but do not decode JSON or dispatch commands until authorization succeeds. | Windows returns error 1368 when `ImpersonateNamedPipeClient` is called before the server has read client data. The explicit current-user/SYSTEM DACL remains the first access barrier. |
| 2026-09-28 | foobar component architecture | Keep framing, protocol, pipe service, idempotency, and PlaybackFacade independent of the foobar SDK; isolate SDK calls in the pending adapter. | This permits real security/contract tests without committing SDK artifacts while preserving a narrow, testable boundary for the pinned 2026-09-17 SDK. |
| 2026-09-28 | Named Pipe discovery | Define `UserSidHash` as lowercase hexadecimal SHA-256 over the canonical Windows SID string's UTF-8 bytes. | The protocol previously omitted the byte encoding and the first C++ draft hashed UTF-16 storage, which a natural Rust implementation would not reproduce. A fixed SID vector now locks cross-language discovery. |
| 2026-09-28 | Foobar snapshot identity | Preserve the schema's nullable `trackId` for every playback status, including `playing` and `paused`; never reuse a stale FishMuse ID for a track started directly inside foobar. | The real SDK can report a current media handle that was never resolved by FishMuse, while privacy rules forbid returning its path. Rust and C++ had added a stricter invariant absent from the shared Schema. Cost if wrong: consumers must render active playback with unknown identity rather than assuming every active item belongs to the FishMuse library. |
| 2026-09-28 | Foobar SDK adapter | Play trusted local handles through a dedicated `FishMuse Playback Bridge` playlist, and defer all playback-callback snapshots outside the SDK callback stack. | The SDK exposes arbitrary-handle playback through playlist operations, while `playback_control` explicitly forbids calls from global callbacks. The bridge does not activate the playlist or access database files; deferred events are cancellable before pipe shutdown. |
| 2026-09-29 | Wrong-SID integration | Validate the DACL with a real secondary-user interactive token, a current-user positive control, and synchronous `CreateFileW` under impersonation instead of requiring a cross-user child process. | Host policy denies cross-user process creation before pipe access. The plan requires a repeatable real-token Windows integration test, not a separate process; direct Win32 access under the verified different SID tests the same kernel DACL and yields the exact error code. |
| 2026-09-29 | GitHub publication | After Task 8 passes and a secret/binary boundary audit is clean, publish the repository as public and push each subsequent task-level commit; do not create a PR or deploy. | The user's latest explicit instruction overrides the earlier no-push constraint while retaining the plan's commit granularity and privacy/security constraints. No push has occurred yet. |

When adding a row, prefer a concise decision and link to the relevant test, plan section, or commit.
